# Руководство по использованию

## Основные операции

### Сохранение контекста

```python
# Сохранение резюме задачи (task summary)
await save_task_summary(
    task="Реализация аутентификации пользователя",
    summary="Добавлена аутентификация на базе JWT с токенами обновления",
    outcomes=["Логин работает", "Управление сессиями реализовано"],
    decisions=["Использован JWT вместо сессий", "Ротация токенов обновления"]
)

# Сохранение знаний (knowledge)
await save_knowledge(
    title="Поток аутентификации",
    content="Пользователь логинится → выдается JWT → сохраняется в cookie → проверяется при каждом запросе",
    topic="authentication",
    importance="high"
)

# Сохранение основной памяти (core memory)
await set_core_memory(
    content="Я предпочитаю чистый код и модульную архитектуру. Избегайте сильной связности.",
    memory_type="persona"
)
```

### Поиск в контексте

```python
# Поиск в основной памяти
results = await search_context(
    query="предпочтения в стиле кодирования",
    collection="core",
    limit=5
)

# Поиск в базе знаний
results = await search_context(
    query="паттерны аутентификации",
    collection="knowledge",
    limit=10
)
```

## Интеграция с OpenCode

### Ключевые слова

Локальная память (через сервер elbruso) позволяет сохранять важные моменты, используя инструменты напрямую или через плагины OpenCode. Если вы используете OpenCode, агент может автоматически вызывать эти инструменты.

### Пример диалога

```
User: Запомни, что я предпочитаю TypeScript вместо JavaScript
Agent: (вызывает elbruso.save_context автоматически)
      Сохранено: "Пользователь предпочитает TypeScript вместо JavaScript"

User: Какие языки я предпочитаю?
Agent: Поиск в памяти... Найдено: "Пользователь предпочитает TypeScript вместо JavaScript"
```

## Лучшие практики

### Перед началом задачи

```python
# Поиск релевантного контекста
context = await search_context(query=f"похожее на: {current_task}", limit=5)
# Используйте контекст в своем подходе
```

### После завершения задачи

```python
# Документирование решений
await save_task_summary(
    task=current_task,
    summary=what_was_done,
    outcomes=[...],
    decisions=[...важные_решения...]
)
```

### При изучении чего-то нового

```python
# Сохранение как знание
await save_knowledge(
    title="Новая концепция",
    content=explanation,
    topic="category",
    importance="medium"
)
```

## Работа с несколькими проектами (Изоляция)

Вы можете изолировать память для разных проектов, используя переменную окружения `PROJECT_NAME`.

### Как это работает
1.  **В Qdrant**: Коллекции будут создаваться с префиксом проекта (например, `web-app_agent_core`).
2.  **В Git (бэкапы)**: Данные будут сохраняться в отдельную ветку Git (например, `memory/web-app`).

### Настройка в OpenCode
Добавьте `PROJECT_NAME` в настройки сервера в `opencode.jsonc`:

```json
"elbruso": {
  "command": "python3",
  "args": ["/path/to/server.py"],
  "env": {
    "PROJECT_NAME": "my-cool-project",
    "QDRANT_URL": "http://localhost:7999"
  }
}
```

### Привязка к репозиторию проекта
Вы можете сохранять бэкапы памяти прямо внутри вашего проекта. Это гарантирует, что контекст всегда будет соответствовать версии кода.

1.  Укажите `PROJECT_PATH` с путем к вашему репозиторию.
2.  Бэкапы будут создаваться в папке `.elbruso/context/` внутри проекта.
3.  Коммиты будут делаться в репозиторий проекта, а не в глобальный контекст.

Пример настройки `PROJECT_PATH` в `opencode.jsonc` был бы излишним для сервера, но для скрипта бэкапа это выглядит так:
`PROJECT_PATH=/home/ivan/git/my-repo python3 scripts/backup.py`

## Советы

1. **Будьте конкретны** — "Асинхронные паттерны Python" лучше, чем просто "Python".
2. **Добавляйте метаданные** — Используйте теги и темы для удобной фильтрации.
3. **Периодически проверяйте** — Используйте `list_collections()`, чтобы увидеть, что сохранено.
4. **Очистка** — Периодически удаляйте неактуальные воспоминания.

## Устранение неполадок

### Нет результатов поиска
- Попробуйте другие ключевые слова.
- Проверьте имя коллекции.

### Память не сохраняется
- Проверьте логи OpenCode.
- Убедитесь, что сервер MCP запущен и доступен.

### Ошибка подключения к Qdrant
- Проверьте: `docker ps | grep qdrant`
- Перезапустите: `docker compose restart qdrant`
- Логи: `docker logs elbruso-qdrant`
