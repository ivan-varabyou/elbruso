# Протокол исправления архитектурных ошибок (для AI-агентов)

Этот документ содержит инструкции для AI-агента по обработке и исправлению ошибок линтера, связанных с архитектурой FEOD.

---

## 1. Типы архитектурных ошибок

### 1.1 `boundaries/element-types` (Нарушение границ слоев)
**Что это значит**: Вы пытаетесь импортировать логику из «верхнего» слоя в «нижний» (например, из `Pages` в `Modules` или из `Modules` в `Common`).
**Как исправить**:
1.  **Анализ**: Проверьте путь файла, в котором произошла ошибка, и путь импортируемого файла.
2.  **Действие**: 
    - Если импортируемая логика специфична для «нижнего» слоя — **перенесите** ее в этот слой или в `Common`.
    - Если логика должна остаться наверху — используйте **Dependency Injection** (передайте функцию/данные через пропсы или аргументы) вместо прямого импорта.
3.  **Запрещено**: Использовать `eslint-disable` для обхода этого правила.

### 1.2 `boundaries/entry-point` (Нарушение Public API)
**Что это значит**: Вы импортируете файл напрямую из внутренностей модуля, минуя его `index.ts`.
**Как исправить**:
1.  **Действие**: Измените путь импорта так, чтобы он заканчивался на названии папки модуля (или указывал на `index.ts`).
2.  **Проверка**: Если нужный символ не экспортирован в `index.ts` модуля — **добавьте** его в экспорт `index.ts`.
3.  **Запрещено**: Импортировать файлы из папок `model/`, `ui/`, `api/` модуля напрямую извне.

### 1.3 `boundaries/no-private` (Доступ к приватному коду)
**Что это значит**: Попытка доступа к коду, который помечен как приватный внутри фрактала.
**Как исправить**: Убедитесь, что вы используете только те части модуля, которые явно разрешены через Public API.

## 2. Иерархия слоев и порядок импортов

### 2.1 Матрица дозволенности импортов
Линтер следит за тем, чтобы зависимости шли только сверху вниз.

| Слой | Описание и Примеры | Ограничения по импорту |
| :--- | :--- | :--- |
| **App Shell** | Лейауты, стили, провайдеры. `src/app/layout.tsx`. | Может импортировать всё. |
| **Pages** | Композиция страницы. `src/pages/Home/page.tsx`. | Только из **Modules** и **Common**. |
| **Modules** | Доменная логика. `modules/Auth`, `modules/Table`. | Только другие **Modules** (через index.ts) и **Common**. |
| **Common** | UI-Kit, Libs, Types. `@repo/ui`, `shared/common`. | Только другие **Common**. **Запрещено** импортировать бизнес-логику. |

### 2.2 Фрактальная вложенность (Nested Modules)
Модули могут содержать подмодули. Правила изоляции работают рекурсивно:
- `modules/Parent` -> `modules/Parent/modules/Child`
- **Child** доступен для **Parent** только через `Child/index.ts`.
- Внешний мир должен обращаться к **Child** через `Parent/index.ts` (если Parent его экспортирует) или напрямую через `Child/index.ts` (если разрешено).

## 3. Общие правила исправления

### 2.1 Стиль кода (`prettier/prettier`)
**Действие**: Всегда запускайте `pnpm exec eslint --fix <file>` или `pnpm run format` после внесения изменений. Не исправляйте кавычки и пробелы вручную.

### 2.2 Чек-лист для агента при ошибке:
1.  **Определить слой**: В каком слое я нахожусь? (App, Pages, Modules, Common).
2.  **Сверить правила**: Разрешен ли этот импорт согласно `docs/FEOD_ARCHITECTURE.md` (раздел 5)?
3.  **Выбрать решение**: Перенос кода (Refactor) или инверсия зависимостей (DI).
4.  **Валидация**: Запустить проверку `pnpm run lint` повторно.
