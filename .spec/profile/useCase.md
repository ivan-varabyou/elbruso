F — обновление данных при изменении источников

🧩 A. Создание таблицы
A1. Создание пустой таблицы
Акторы: пользователь
Цель: создать новую таблицу в воркспейсе

Предусловия:

Пользователь имеет права can_create_tables.

Сценарий:

Пользователь нажимает «Создать таблицу».

Вводит название таблицы.

Выбирает тип таблицы:

пустая

по шаблону

на основе справочника

Таблица создаётся с 1 колонкой и 0 строк.

Открывается в центральной области.

Ошибки:

Нет прав → сообщение.

Название занято → предложение добавить суффикс.

A2. Создание таблицы на основе справочника
Акторы: пользователь
Цель: создать таблицу, где вертикаль формируется автоматически

Предусловия:

В системе есть справочники (регионы, критерии, организации).

Сценарий:

Пользователь выбирает «Создать таблицу → На основе справочника».

Выбирает справочник (например, «Регионы РФ»).

Выбирает фильтры (страна = Россия).

Система создаёт таблицу:

первая колонка = справочник

строки = элементы справочника

Таблица открывается.

Ошибки:

Справочник недоступен по правам.

Справочник пуст.

A3. Создание таблицы по шаблону
Сценарий:

Пользователь выбирает шаблон.

Система создаёт таблицу с:

колонками

типами данных

формулами

связями

Таблица открывается в режиме черновика.

🧩 B. Работа со структурой таблицы
B1. Добавление колонки
Сценарий:

Пользователь нажимает «+ Колонка».

Выбирает тип:

число

текст

дата

булево

ссылка на справочник

формула

Колонка добавляется.

B2. Добавление строк
Сценарий:

Пользователь нажимает «+ Строка».

Строка появляется внизу.

Если таблица основана на справочнике → строка заблокирована для ручного добавления.

B3. Изменение порядка колонок
Drag & drop.

🧩 C. Связи внутри воркспейса
C1. Связь «lookup» с другой таблицей
Акторы: пользователь
Цель: подтянуть данные из другой таблицы

Предусловия:

Обе таблицы находятся в одном воркспейсе.

Сценарий:

Пользователь выбирает колонку → «Связать с таблицей».

Выбирает таблицу-источник.

Выбирает колонку-ключ (например, «Регион»).

Выбирает колонку-значение (например, «Население»).

Система создаёт связь.

Данные автоматически подставляются.

Ошибки:

Несовместимые типы ключей.

Нет совпадений → пустые значения.

C2. Связь «join» (многие-к-одному)
Сценарий:

Пользователь выбирает «Добавить связь».

Выбирает тип «join».

Настраивает:

таблица A

таблица B

ключи

Система создаёт виртуальную колонку.

C3. Связь «reference» (ссылка на строку другой таблицы)
Сценарий:

Пользователь выбирает тип колонки «Ссылка».

Выбирает таблицу.

Выбирает отображаемое поле.

В ячейке появляется выпадающий список.

🧩 D. Связи между воркспейсами
D1. Импорт данных из другого воркспейса (read-only)
Сценарий:

Пользователь выбирает «Связать с внешним воркспейсом».

Выбирает воркспейс.

Выбирает таблицу.

Система создаёт read-only связь.

При изменении источника появляется уведомление:

«Источник обновился. Обновить данные?»

D2. Агрегация данных из нескольких воркспейсов
Сценарий:

Пользователь создаёт таблицу «Агрегатор».

Выбирает:

список воркспейсов

таблицу

поля

Система собирает данные в единую таблицу.

🧩 E. Формулы и HUD
E1. Создание формулы
Сценарий:

Пользователь вводит =.

Включается HUD:

текущая формула

подсказки функций

подсветка ячеек

Пользователь кликает по ячейкам в других таблицах.

HUD показывает:

путь к ячейке

предварительный результат

Формула сохраняется.

E2. Формула с межтабличной ссылкой
Сценарий:

Пользователь вводит =.

Переходит в другую таблицу.

HUD остаётся на экране.

Пользователь выбирает ячейку.

Система вставляет ссылку вида:

Код
=TABLE("Население").COLUMN("2024").ROW("Москва")
E3. Ошибки формул
циклическая зависимость

ссылка на удалённую колонку

неверный тип данных

деление на ноль

HUD показывает ошибку в реальном времени.

🧩 F. Обновление данных при изменении источников
F1. Источник изменился
Сценарий:

Пользователь изменяет таблицу-источник.

Система обновляет граф зависимостей.

Все связанные таблицы получают статус:

«Требуется обновление»

Пользователь нажимает «Обновить».

Формулы пересчитываются.

F2. Автоматическое обновление
Если включено:

пересчёт происходит мгновенно.

🧩 G. Версии, черновики, публикации
G1. Создание черновика таблицы
Сценарий:

Пользователь нажимает «Редактировать таблицу».

Создаётся черновик.

Все изменения идут в черновик.

G2. Публикация изменений
Сценарий:

Пользователь нажимает «Публиковать».

Система показывает diff:

добавленные колонки

изменённые формулы

изменённые связи

Пользователь подтверждает.

Создаётся новая версия таблицы.

G3. Откат версии
Сценарий:

Пользователь открывает историю версий.

Выбирает версию.

Нажимает «Откатить».

Таблица возвращается к состоянию версии.
