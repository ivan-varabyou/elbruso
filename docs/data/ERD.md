Опишу систему так, как будто мы уже её запускаем в прод: что она умеет, кто в ней живёт, какие процессы закрывает, и как всё это логически связано. Без лишней романтики, только то, что даёт тебе власть над этой кашей из Excel.

1. Общая идея системы
Это централизованная платформа оценки развития баскетбола (и потенциально других видов спорта) по регионам и федерациям.

Она:

хранит нормализованные справочники (страны, регионы, округа, виды спорта, организации);

держит базу показателей (критериев) с группами, весами, полом, дисциплинами и учётом населения;

хранит фактические значения по каждому показателю для каждого региона/федерации и сезона;

умеет считать итоговые баллы и рейтинги;

позволяет гибко изменять критерии (добавлять, выключать, менять веса) без ломки данных;

готова к AI‑аналитике (поиск закономерностей, рекомендаций, сценариев).

На этом уровне нет конкретных команд/игроков — только агрегированные значения (количество, наличие, баллы).

2. Справочники и структура мира
2.1. География
Система знает:

страны (RU, BY, KZ и т.д.);

федеральные округа / макрорегионы (для РФ, BY, KZ — твоя логика уже есть);

субъекты/регионы (Москва, Татарстан, Алтайский край и т.д.);

типы регионов (республика, край, область, город федерального значения).

Функциональность:

Навигация и фильтрация: смотреть показатели по стране, округу, региону;

Сравнение: “топ‑10 регионов РФ по развитию массового баскетбола 3x3”;

Демография: хранение населения региона по годам, чтобы нормализовать показатели “на 100k жителей”.

2.2. Организации
Система знает:

уровень организации: международный, национальный, региональный, клубный;

тип организации: национальная федерация, региональная федерация, лига, любительская лига, спортшкола, комитет, департамент;

конкретные организации: РФБ, региональные федерации, АСБ, МЛБЛ, КЭС‑Баскет и т.д.

Функциональность:

построение иерархии спорта: IOC → FIBA → РФБ → региональные федерации → лиги → клубы;

привязка показателей к конкретной федерации/организации, а не просто к региону (но на верхнем уровне можно работать через регион).

3. Спорт, дисциплины и “ось измерения”
Система понимает:

вид спорта: баскетбол (BBL), потом можно добавить футбол, волейбол и т.п.;

дисциплины: 5x5, 3x3, в будущем — кибербаскетбол;

пол: мужской, женский;

возрастные группы: U14, U15, U18, студенты, ветераны, взрослые.

Функциональность:

разделение показателей по дисциплинам (5x5 и 3x3 — разные миры, но в одной базе);

разделение по полу и возрасту (сборные U18 мужчины ≠ сборные U18 женщины);

возможность строить отчёты как по совокупности, так и отдельно:

“весь баскетбол в регионе”

“только 5x5”

“только женщины 3x3 U18”

4. Система показателей (главное ядро)
Это то, что заменяет Excel.

4.1. Группы показателей
Каждый показатель относится к логической группе, например:

Региональная федерация

Маркетинг федерации

Общие критерии для региона

Спортивные объекты

Сборные команды России 5x5

Сборные команды России 3x3

Профессиональный баскетбол 5x5

Профессиональный баскетбол 3x3

Резерв 5x5

Резерв 3x3

Массовый баскетбол 5x5

Массовый баскетбол 3x3

Баскетбольные мероприятия 5x5

Баскетбольные мероприятия 3x3

Судьи 5x5

Судьи 3x3

Тихий баскетбол

Интерактивный баскетбол

Прочее

Функциональность:

логическая навигация по системе, а не “800 колонок Excel”;

возможность агрегировать баллы по группе (например, “Маркетинг федерации = сумма всех показателей её блока”);

гибкость: можно добавлять подгруппы (Локобаскет, КЭС‑Баскет, АСБ, МЛБЛ, ветераны и т.д.).

4.2. Показатели (indicators)
Каждый показатель — это сущность с параметрами:

ID/код (стабильный, не зависящий от формулировки);

название (то, что ты видишь в Excel: “Команда в ПР юноши до 16 лет (финал)”);

группа (см. выше);

вид спорта / дисциплина (5x5/3x3);

пол (если релевантно);

возрастная группа (если релевантно);

тип значения:

число (кол-во команд, игроков),

булево (есть/нет),

может быть decimal (балл напрямую);

вес (баллы за единицу — то, что у тебя в отдельной таблице “Баллы за единицу”);

признак “учёт населения” (да/нет — если да, при аналитике нормализуем на 100k жителей);

описание (строгое текстовое правило из твоих комментариев);

источник (табличка/анкета/официальный сайт/РФБ/Минспорт).

Функциональность:

единый справочник всех вопросов/критериев (вместо надписей по колонкам Excel);

возможность менять веса, названия, активность без потери исторических данных;

фильтрация: “показать все показатели, относящиеся к массовому 3x3 мужчины U18”.

5. Значения показателей (то, что сейчас в Excel по регионам)
5.1. Кто/где заполняет
На верхнем уровне:

носитель данных = регион/федерация (по сути, для РФ — это субъект РФ + его федерация).

Мы храним:

регион (или федерация, если заведём отдельную сущность),

сезон (год или спортивный сезон),

показатель,

значение.

5.2. Как это выглядит логически
Для каждой комбинации:

регион (например, Татарстан),

сезон (2024),

показатель (“Команды в ПР юноши до 14–16 (финал)”)

система хранит:

value = число (0, 1, 2, 3…);

технические поля (кто и когда ввёл, источник, комментарий).

Это ровно то, что сейчас у тебя в Excel, только:

не в виде тысячи колонок,

а в виде нормализованной факт‑таблицы.

Функциональность:

возможность добавлять новые показатели, не меняя структуру таблиц (просто появляются новые строки, не колонки);

возможность хранить несколько сезонов;

возможность считать динамику (рост/падение показателей).

6. Сезоны, версии, пересчёт
6.1. Сезоны
Каждый показатель и его значение привязан к сезону (или году).

Функциональность:

видеть рейтинг по конкретному сезону;

сравнивать сезоны между собой;

хранить историю.

6.2. Версионирование показателей (по необходимости)
Если в будущем веса/формулировки меняются, система может хранить версии:

версия 1 — веса/описания, действовавшие до 2024;

версия 2 — новая редакция, действующая с 2024/25.

Функциональность:

корректно пересчитывать прошлые годы;

изменять критерии без потери адекватности исторических данных.

7. Расчёт итоговых баллов и рейтингов
7.1. Механика расчёта
Для каждого:

региона/федерации,

сезона

система:

Берёт все активные показатели.

Для каждого:

берёт value,

умножает на weight,

если “учёт населения = да” — нормализует на население (через region_population).

Складывает по:

группам,

дисциплинам,

полу,

общую сумму.

Результат:

итоговый балл региона;

разбивка по блокам (федерация, профессиональный баскетбол, массовый, судьи, 3x3 и т.п.);

можно сделать композиции: “сколько очков регион набрал за женский баскетбол 3x3”.

7.2. Хранение результата
Итог можно:

считать “на лету”,

либо складывать в таблицу federation_scores (регион/федерация, сезон, итоговый балл, JSON‑детализация).

Функциональность:

строить рейтинги: топ‑N регионов, сравнение регионов;

делать срезы: “в каких регионах сильный массовый 3x3, но слабые судьи 5x5”.

8. Работа пользователей (роли и сценарии)
8.1. Кто может быть в системе
Администраторы (центральный офис РФБ):

управляют справочниками,

создают/изменяют показатели,

настраивают веса и группы,

утверждают сезоны.

Региональные представители:

вводят/обновляют значения показателей по своим регионам,

прикладывают документы (если понадобится).

Аналитики:

строят отчёты и выгрузки,

делают сравнения,

готовят презентации/решения.

8.2. Основные сценарии работы
Настройка системы критериев:

создать/изменить группы показателей,

завести новый показатель (например, новый формат турнира),

привязать к группе, виду спорта, дисциплине, полу, возрасту,

назначить вес,

включить/выключить для конкретных федераций.

Сбор данных:

регион/федерация открывает форму по сезону,

видит список показателей, которые для него актуальны,

заполняет values (числа/галочки),

сохраняет/отправляет на проверку.

Проверка/верификация:

центральный офис проверяет подозрительные значения,

возвращает на доработку,

при необходимости фиксирует комментарии/источники.

Расчёт рейтингов:

система считает баллы по регионам,

строит сводную таблицу (аналог твоей “Субъект РФ / Коэф / Сумма баллов / Муж / Жен / 5х5 / 3х3 / …”, но уже на базе нормализованных данных),

позволяет выгрузить в Excel/CSV/BI.

Аналитика:

какие показатели сильнее всего влияют на общий рейтинг?

какие группы отстают?

где сильный резерв, но слабая инфраструктура?

где сильные судьи, но слабый массовый спорт?

9. Как система специально учитывает твои требования
9.1. Верхнеуровневое хранение (без команд)
никаких таблиц команд/игроков/матчей на этом этапе;

только агрегаты: количество команд, количество воспитанников, факты участия и призов;

это значительно упрощает модель и ускоряет запуск, не блокируя детализацию в будущем.

9.2. Гибкость и масштабируемость
хочешь добавить новый турнир — создаёшь новый показатель, не меняя схему;

хочешь новый блок критериев — новая группа;

хочешь подключить новый вид спорта — просто добавляешь sport + новые показатели;

хочешь работать с BY/KZ/любой другой страной — база уже готова по географии и источникам.

9.3. Замена Excel, а не копия Excel
таблица “Субъект РФ / Коэф / Сумма баллов / … 300+ колонок”
→ превращается в:

справочник показателей,

факт‑таблицу значений,

механизм расчёта и агрегирования.
